# RK3588 SD Card Flash Notes

This OpenCCA workspace targets SD-card boot, not eMMC.

`rkdeveloptool --help` reports the Rockchip storage IDs as:

```text
ChangeStorage: cs [storage: 1=EMMC, 2=SD, 9=SPINOR]
```

Use storage ID `2` for SD-card firmware, kernel-slot, and full-image writes.
The wrapper defaults are:

```text
OPENCCA_FIRMWARE_STORAGE_ID=2
OPENCCA_ROOTFS_STORAGE_ID=2
OPENCCA_KERNEL_STORAGE_ID=2
```

The wrapper refuses SD firmware, rootfs, and kernel-slot writes when the selected
storage ID does not match `OPENCCA_SD_STORAGE_ID`.

## Current SD Layout

The current ROCK 5B SD card uses a separated boot-kernel/rootfs layout:

```text
loader1 start=0x40
loader2 start=0x4000
kernel start=0x8000  size=0x40000 sectors  label=kernel
root   start=0x48000 label=root
```

The `kernel` partition is a fixed 128 MiB ext4 boot filesystem. It contains
`/boot/extlinux/extlinux.conf`, the Linux image, initrd, and Rock 5B DTB.
U-Boot uses `CONFIG_BOOTCOMMAND="bootflow scan"`, so the boot path stays close
to the stock OpenCCA Debian extlinux/initrd flow while still allowing p3 to be
rewritten independently.

Verified on 2026-06-11:

```text
/dev/mmcblk1p3 128M ext4 label=kernel partlabel=kernel
/dev/mmcblk1p4 3.7G ext4 label=root   partlabel=root mounted at /
root=PARTLABEL=root rootwait isolcpus=1,2,3 maxcpus=2 nohlt cpuidle.off=1 rcupdate.rcu_cpu_st maxcpus=2
```

## Build The Kernel Boot Partition

Build the extlinux kernel partition from local kernel artifacts:

```bash
./scripts/image/build-raw-kernel-image.sh \
  --image snapshot/vmlinuz-6.12.0-opencca-wip \
  --initrd snapshot/initrd.img-6.12.0-opencca-wip \
  --dtb snapshot/rk3588-rock-5b.dtb \
  --root PARTLABEL=root \
  --output snapshot/kernel-extlinux.img
```

If those files are not in `snapshot/`, pass absolute paths extracted from the
OpenCCA rootfs image. The output file defaults to `snapshot/kernel-extlinux.img`,
is exactly 134217728 bytes, and is ignored by Git.

Known-good image recorded on 2026-06-11:

```text
snapshot/kernel-extlinux.img
sha256=5b41a8d86bdc52722ca20c4d81a2e9fc4db230b4de4b19c44430beae81ccbc2e
```

## Convert An Old OpenCCA Image Once

Older OpenCCA images have `root` at `0x8000`, so writing a kernel there would
overwrite rootfs. Convert the old image once before using kernel-only flashes:

```bash
python3 scripts/image/convert-opencca-image-to-raw-kernel-layout.py \
  rootfs/opencca-image-rockchip-rock5b-rk3588.img \
  rootfs/opencca-image-rockchip-rock5b-rk3588-extlinux-kernel.img \
  --kernel snapshot/kernel-extlinux.img
```

The converted image keeps loader partitions, writes the ext4 kernel boot
partition at p3/LBA `0x8000`, and moves rootfs to p4/LBA `0x48000`.

Flash the converted full image to SD:

```bash
OPENCCA_ROOTFS_IMAGE=$PWD/rootfs/opencca-image-rockchip-rock5b-rk3588-extlinux-kernel.img \
OPENCCA_RPI_PASSWORD=root OPENCCA_RPI_SUDO_PASSWORD=root OPENCCA_RK_PASSWORD=root \
  ./scripts/firmware/flash-rk3588-via-pi.sh \
  --sync-rootfs --flash-rootfs --wait-rk
```

If SSH host keys were regenerated by the fresh rootfs, clear the temporary known
hosts file and re-check:

```bash
ssh-keygen -f /tmp/opencca_known_hosts -R 192.168.31.18
sshpass -p root ssh -o StrictHostKeyChecking=accept-new \
  -o UserKnownHostsFile=/tmp/opencca_known_hosts \
  root@192.168.31.18 'hostname; uname -a; findmnt -no SOURCE,TARGET,FSTYPE /; lsblk -o NAME,SIZE,FSTYPE,LABEL,PARTLABEL,MOUNTPOINT'
```

Expected root source after conversion: `/dev/mmcblk1p4 / ext4`.

## Flash Only The Kernel Partition

After the compatible SD layout is present, flash only the SD kernel boot slot:

```bash
OPENCCA_RPI_PASSWORD=root OPENCCA_RPI_SUDO_PASSWORD=root OPENCCA_RK_PASSWORD=root \
  ./scripts/firmware/flash-rk3588-via-pi.sh \
  --kernel-image snapshot/kernel-extlinux.img \
  --flash-kernel --wait-rk
```

The wrapper first performs a live RK partition preflight. The Pi-side helper then
enters Maskrom, transfers the SPL loader, selects Rockchip storage ID `2`, reads
GPT with `rkdeveloptool rl`, validates `PARTLABEL=kernel` at LBA `0x8000`, and
writes only that kernel partition with `rkdeveloptool wl 0x8000 ...`.

This kernel-only path was verified on 2026-06-11. The board came back over SSH
with root still mounted from `/dev/mmcblk1p4`.

## Direct Raspberry Pi Equivalent

For full-image SD flashing through the Pi:

```bash
cd /home/mzh/opencca-flash
printf "%s\n" root | sudo -S env OPENCCA_ROOTFS_STORAGE_ID=2 \
  ./flash.sh rootfs snapshot/opencca-image-rockchip-rock5b-rk3588-extlinux-kernel.img --yes
```

For kernel-only flashing, prefer the wrapper above because it syncs the helper
scripts and preserves the live preflight. The Pi-side helper is:

```bash
cd /home/mzh/opencca-flash
printf "%s\n" root | sudo -S env \
  OPENCCA_KERNEL_STORAGE_ID=2 \
  OPENCCA_KERNEL_IMAGE=/home/mzh/opencca-flash/snapshot/kernel-extlinux.img \
  ./opencca-scripts/firmware/flash-raw-kernel-on-pi.sh
```

## Source Configuration

To make local source checkouts generate the same layout:

```bash
./scripts/firmware/configure-raw-kernel-slot-sources.sh
```

This sets U-Boot to `bootflow scan` and updates `debian-image-recipes` so the
image contains p3 `kernel` ext4 and p4 `root` ext4. The helper name still says
`raw-kernel` for compatibility with earlier patch notes, but the current working
kernel slot is an ext4 extlinux boot partition.
